# DataTable Action Buttons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide consistent, accessible, responsive action buttons across administrative DataTables.

**Architecture:** A layout-level Blade partial owns the shared visual rules and enhances existing Bootstrap action classes only inside DataTable cells. The Form Links listing uses explicit semantic classes for its view, edit, status, delete, and copy controls while retaining its existing endpoints and handlers.

**Tech Stack:** Laravel 8 Blade, Bootstrap, Font Awesome, PHPUnit.

**Spec:** `docs/superpowers/specs/2026-10-27-data-table-actions-design.md`

## Global Constraints

- Preserve existing routes, form methods, permissions, and JavaScript handlers.
- Minimum interactive target is 44 by 44 pixels.
- Action groups wrap on narrow table columns.
- No new frontend dependency.

## Review Focus

- Icon-only controls need an accessible name and a visible keyboard focus state.
- Forms nested in action groups must not add margins or break alignment.
- Existing action buttons generated by DataTables must inherit the shared styles.
- Text actions must expand beyond the minimum target without clipping.
- Narrow columns must wrap rather than overlap adjacent content.
